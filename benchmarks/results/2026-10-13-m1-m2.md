# S26 M1 / M2 — network isolation and multi-app control validation

Date: 2026-10-13
Device: Samsung SM-S948B / Android API 37
Execution: Project IR -> ops -> USB ADB for controlled isolation and measurement.

## M1: isolated local operation

Hypothesis: already-running Shizuku and the native Project IR Accessibility bridge survive loss of all phone radios.

**First trial:** Airplane Mode, 12/12 local provider and Shizuku process observations PASS. This was not accepted as strict-offline proof, because Android can retain Wi-Fi in Airplane Mode.

**Strict trial:** Airplane Mode on, Wi-Fi off, mobile data off, and no IPv4 default route. Verified eight times:
- local Project IR Accessibility provider: 8/8 PASS;
- Shizuku server and Project IR UserService processes: 8/8 PASS;
- prior radio settings restored exactly: airplane=0, wifi=1, mobile_data=1.

Raw evidence: ../m1/20261013-airplane-offline.json and ../m1/20261013-strict-offline.json.

USB ADB remained connected as a recovery path. This proves local bridge and process persistence during the tested offline period, **not** that a cloud-hosted Project IR Hub can work without Internet, nor that privileged execution through the UserService was actively performed while offline. The ~1–1.8-second observed request timings include ADB/ContentProvider overhead and are **not** native Accessibility action latency.

M1 bounded offline feasibility: **GO**.
Full M1 endurance: **HOLD**, pending longer tests, unplugged USB, direct offline autonomous actions, battery/thermal metrics, and reboot recovery.

## M2: multi-app structured UI

The first test launched Settings, Calculator and Maps successfully, each yielding six valid snapshots. Samsung Clock failed at its package-scoped implicit launcher Intent: this was a **launch failure**, not a tree failure.

The corrected test used the explicitly resolved Clock launcher activity. It passed:

| Application | Snapshots | Nodes observed | ADB/provider p50 |
| --- | ---: | ---: | ---: |
| Samsung Settings | 6/6 | 119 | 1012.25 ms |
| Samsung Calculator | 6/6 | 36 | 1006.54 ms |
| Samsung Clock | 6/6 | 120 | 1019.82 ms |
| Google Maps | 6/6 | 314 | 1028.85 ms |

All structured snapshots: **24/24 PASS**.

An independent Settings workflow repeated semantic Connections click -> Wi-Fi/Bluetooth verification -> Back -> root verification ten times: **10/10 PASS**.

Raw evidence: ../m2/20261013-multi-app-v1-clock-launch-fail.json and ../m2/20261013-multi-app-smoke.json.

The benchmark stores package names, node counts, timings and narrow failure classes but not screen contents or messages. The device foreground was restored to ChatGPT. Timings include ADB shell startup and provider access: they must not be used as the intrinsic on-device tree latency.

M2 selected-app read-only perception feasibility: **GO**.
Full M2 agent reliability: **HOLD** for dynamic scrolling, typed input in more apps, permission popups, side-effect verification and statistically meaningful high-reliability trials.

## Speech / NPU discovery only

Read-only Android inventory:
- model: SM-S948B, platform: QTI SM8850 / canoe, SDK 37;
- Android RecognitionService query found three services: Google TTS recognition, Claude, OpenAssistant;
- conventional vendor/system QNN library filename glob matched zero files;
- conventional vendor/system TensorFlow/TFLite filename glob matched nine files.

These are discovery observations only. A missing system filename is not proof that Qualcomm NPU acceleration is unsupported; libraries can be app-bundled or named differently. Registered recognition services do not establish offline Persian support, accuracy, inference backend or privacy.

Next fair ASR benchmark: same real Persian-English corpus, local platform recognizer versus compatible sherpa-onnx Persian pipeline versus on-device Whisper; report cold/warm p50 and p95, WER/CER, memory, power and offline capability. Next NPU benchmark must compare actual supported QNN/LiteRT execution with CPU using the same model and inputs. No models were downloaded or installed; no microphone recording was made.

## Reboot safety and restoration

No unattended Shizuku restart procedure was verified. Rebooting now could strand privileged remote execution until manual/USB intervention, so no reboot was induced.

At final verification:
- airplane=0, wifi=1, mobile_data=1 (same as initial);
- Project IR Hub: connected;
- Shizuku: running, UID 2000;
- native Accessibility provider: connected;
- foreground: ChatGPT.
